# Диагностическая прошивка NMSE OLEDer

Файл `Arduino_RS485_OLEDer_Debug.ino` предназначен для поиска неисправностей платы без FastAPI и EXE. Он проверяет PCA9548A, ADS1115, MCP4728 и сырые измерительные каналы.

## Как запустить

1. Откройте `Arduino_RS485_OLEDer_Debug.ino` в Arduino IDE.
2. Выберите свою плату Arduino Uno или Nano и правильный COM-порт.
3. Установите библиотеки:
   - `Adafruit ADS1X15`;
   - `Adafruit MCP4728`;
   - зависимости, которые Arduino IDE предложит установить автоматически.
4. Загрузите скетч.
5. Откройте `Сервис -> Монитор порта`.
6. Установите `9600 baud` и окончание строки `Newline` или `Both NL & CR`.
7. Сначала отправьте `PING`, затем `AUTO`.

Отлаживайте по одной плате. У диагностической прошивки нет адреса платы, поэтому две платы на одной активной RS-485 шине ответят одновременно.

## Основные команды

```text
PING
STATUS
AUTO
SCAN
MUXSCAN
SAMPLE 1
ALL
MONITOR 1 1000
STOP
ADS 0 1 2/3 10
ZERO
```

`AUTO` безопасно обнуляет ЦАП, проверяет ожидаемые микросхемы и один раз читает четыре образца.

Ожидаемые строки исправной четырёхканальной платы:

```text
CHECK,PCA9548A,ADDR=0x70,OK
CHECK,ADS_12,MUX=0,ADDR=0x48,OK
CHECK,DAC_12,MUX=1,ADDR=0x60,OK
CHECK,ADS_34,MUX=2,ADDR=0x48,OK
CHECK,DAC_34,MUX=3,ADDR=0x60,OK
CHECK,ADS_PHOTO,MUX=4,ADDR=0x48,OK
```

Если какая-либо строка заканчивается `FAIL`, проверять нужно именно указанный канал PCA, питание и линии SDA/SCL соответствующего модуля.

## Проверка ADS1115

Формат:

```text
ADS <канал_PCA> <вход_ADS> <gain> <число_измерений>
```

Пример: десять раз прочитать ток первого образца:

```text
ADS 0 1 2/3 10
```

Пример: проверить слабый фотосигнал первого образца с gain 16:

```text
ADS 4 0 16 10
```

## Безопасная проверка MCP4728

Команда `DAC` заблокирована после запуска. Для одиночной проверки сначала отключите OLED, затем выполните:

```text
ARM YES
DAC 1 0 0.200
ZERO
```

Это подаст 0.2 В с выхода A MCP4728 на канале PCA 1, а затем обнулит все найденные ЦАП. Разблокировка автоматически заканчивается через 30 секунд.

Не подавайте тестовое напряжение на подключённый OLED, пока силовая часть платы не проверена мультиметром.

## Соответствие образцов

| Образец | U/I ADS | Входы ADS | DAC | Выходы DAC | Фото |
|---|---:|---|---:|---|---|
| 1 | PCA 0 | A0 / A1 | PCA 1 | A / B | PCA 4, A0 |
| 2 | PCA 0 | A2 / A3 | PCA 1 | C / D | PCA 4, A1 |
| 3 | PCA 2 | A0 / A1 | PCA 3 | A / B | PCA 4, A2 |
| 4 | PCA 2 | A2 / A3 | PCA 3 | C / D | PCA 4, A3 |

## Что прислать для разбора

Скопируйте полный вывод команд `AUTO` и `MUXSCAN`. По нему можно определить, какой модуль или провод не отвечает.

## Глубокая проверка всех напряжений

Главная безопасная команда:

```text
DEEP 20
```

Она обнуляет ЦАП, оценивает питание Arduino, делает по 20 измерений на каждом входе каждого найденного ADS1115 и выводит:

- среднее напряжение `MEAN_V`;
- минимальное и максимальное напряжение;
- размах шума `P2P_MV`;
- минимальный и максимальный код АЦП;
- признак насыщения `SAT`;
- пересчитанные напряжение и ток каждого образца.

Только все физические входы всех ADS1115, без дополнительной сводки:

```text
RAWALL 2/3 50
```

Статистика одного образца, включая фотоканал с gain 16:

```text
SAMPLESTATS 1 50 16
```

Оценка питания Arduino через внутренний источник 1.1 В:

```text
RAILS
```

Значение `RAILS` является ориентировочным. Точное питание 5 В всё равно нужно проверить мультиметром.

## Автоматическая характеристика ЦАП → АЦП

Этот тест изменяет напряжение. Сначала отключите OLED либо убедитесь, что выбранный диапазон безопасен. Команда отдельно защищена:

```text
ARM SWEEP
SWEEP 1 U 0.0 1.0 0.1 300
```

Параметры означают: образец 1, канал уставки напряжения, от 0 до 1 В на ЦАП, шаг 0.1 В, ожидание 300 мс после каждой точки. В каждой точке выводятся:

```text
SET_DAC_V,U_ADC_V,U_APPROX_V,I_ADC_V,I_APPROX_MA,PHOTO_ADC_V
```

Для канала уставки тока используется режим `I`:

```text
ARM SWEEP
SWEEP 1 I 0.0 0.5 0.05 300
```

После sweep прошивка автоматически выставляет все выходы ЦАП в 0 В и снова включает блокировку. За один запуск допускается не более 100 точек.
